# 按键波形实测归档

> 日期：2026-10-12
> 目的：验证「按键抖动导致跳两页」这个根因推断是否成立

---

## 一、为什么要做这个测量

`按键消抖与EXTI中断` 这个坑的结论是：**20ms 消抖窗口不够，导致一次按键被当成两次（跳两页）**，改成 200ms 后解决。

但这里的根因是**根据现象反推的推断**，没有直接证据：

- 代码层面：git 历史里 `Hardware/Button.c` **首次提交时消抖值就已经是 200ms**，查不到 20ms 那版
- 波形层面：当时**没有用任何仪器**抓过按键波形

所以这次用逻辑分析仪补上证据。

---

## 二、测量方法

| 项 | 说明 |
|----|------|
| 仪器 | NanoDLA 逻辑分析仪（8 通道）+ PulseView |
| 探针 | CH0 → STM32 **PB0**（左键），GND → 板子 GND（**必须共地**） |
| 触发 | D0 下降沿 |
| 按键 | PB0 配置为 `GPIO_Mode_IPU`，空闲高电平，按下变低 |

### 关键点：探针要接在「引脚」上

按键消抖是**纯软件**的时间判断：

```c
if ((now - xLastLeftTick) >= pdMS_TO_TICKS(200))
```

它只决定「这次中断要不要理」，**不改变引脚上的电压波形**。所以逻辑分析仪探在引脚上，看到的是最原始的信号——软件怎么判都影响不到它。

（如果哪天加了**硬件消抖**（RC 滤波 + 施密特触发器），那才会真的改变波形，届时探针要接在滤波电路**之前**才能看到抖动。）

---

## 三、测量参数

| 参数 | 值 | 用途 |
|------|-----|------|
| 采样率 | 100 kHz / 1 MHz 两档 | 100kHz 换更长窗口，1MHz 换更高分辨率 |
| 采样深度 | 1 M | 100kHz → 10 秒窗口；1MHz → 1 秒窗口 |
| 触发 | D0 下降沿，位置 5% | 从按下瞬间开始录 |

**软件消抖值不影响测量**：测量期间代码里是 200ms，但那是软件行为，引脚波形与它无关。

---

## 四、结果：15 次按压，零异常

| 测量 | 次数 | 结果 |
|------|------|------|
| 单次按键（1 秒视野） | 3 | 只有 1 降 1 升 |
| 单次按键（3ms 视野，µs 级） | 2 | 边沿干净，无跳变 |
| 连续按键（10 秒视野） | 10 | 10 组，全部干净 |
| **合计** | **15** | **零异常** |

**结论：这颗按键按下/松开时没有可见抖动。原「抖动漏过窗口」的根因假设不被数据支持。**

问题确实修好了（改 200ms 后不再复现），但**根因没有坐实**。

## 六、附带修正的一条错误推理

早期文档里写过：

> ~~"EXTI 是纯下降沿触发 → 松开抖动不触发中断，排除松开路径"~~

**这条推理是错的。** 松开时引脚整体由低升高，但触点**回弹**会产生短暂低电平——每一次由高变低都是下降沿，**照样触发中断**。而且它能通过 ISR 里的电平确认（`Button_IsLeftPressed()`），因为触点闭合那一刻引脚确实是低。

**教训**：不要用「趋势」（松开 = 上升）去否定「抖动」（期间可能有下降沿），这两件事不矛盾。

---

## 七、怎么复现

1. PulseView 连接 `fx2lafw` 设备
2. 采样率设 100 kHz，采样深度 1 M
3. CH0 → PB0，GND → 板子 GND（共地）
4. 点 Run（可设 D0 下降沿触发），按几次左键，Stop
5. 缩小到整屏看「有几次跳变」，再放大到边沿看细节

## 八、这次测量的收获

不是「抖动导致跳两页」，而是：

> **「修好了」≠「知道为什么修好了」**

调试顺序应该反过来：**先取证，再改代码**。当时的做法是先改代码、问题消失、就当成结论——省了一步验证，结果留下了一个自己讲不清的根因。
