# 系统设计图

用时序图和状态机图描述系统的**运行时行为**。源文件是 PlantUML 纯文本 —— 改起来方便、能进 git diff。

## 文件说明

| 文件 | 画的是什么 |
|------|-----------|
| `01-task-sequence.puml` / `.png` | **任务时序图** —— 一次按键从硬件到屏幕的完整链路，**跨越 中断 / RTOS / 任务 / 驱动 四层** |
| `02-menu-state-machine.puml` / `.png` | **菜单状态机** —— 三个页面的循环切换与转移条件 |

## 为什么要画这两张

- **时序图**：把散落在 `stm32f10x_it.c`、`main.c`、`Menu.c`、`OLED.c` 里的调用关系，**压成一条时间线**，一眼看清顺序和依赖
- **状态机图**：**穷举**所有状态和所有转移。少一个就露馅 ——
  > 画这张图时发现：文档里写的"第二版分层菜单（`MenuState_t`）"**代码里根本没实现**，全工程搜不到该结构体。详见知识库的开发日志坑8。

## 怎么改 / 怎么重新导出

1. 打开 <https://www.plantuml.com/plantuml/uml/>
2. 把 `.puml` 文件内容**整个粘贴**到左边输入框
3. 右边**即时出图**（没有"运行"按钮）
4. 在图上**右键 → 图片另存为**，存成同名 `.png` 放到本目录
5. 提交时把 `.puml`（源）和 `.png`（图）**一起提交**

> **为什么两个都要提交**
> - `.puml` 是**可编辑的源文件** —— 改一行、git diff 看得见
> - `.png` 是**渲染结果** —— GitHub 上 README 直接引用它来显示
>
> 只提交 PNG 的话，以后想改图得从头重画；只提交 PUML 的话，别人打开仓库看不到图。

## ⚠️ 一个必须遵守的约定

**改完 `.puml` 一定要重新导出 PNG。**

否则源文件和图片会不一致 —— 这正是本项目在别处踩过的坑（**文档说 A，代码是 B**）：

| 已经踩过的同类坑 |
|-----------------|
| 开发日志写"用示波器看波形"，但根本没有示波器 |
| 代码注释写"关闭连续转换"，实际是 `ENABLE` |
| 文档写"第二版分层菜单"，代码里没这个结构体 |

**图文不一致也是同一种病。**
