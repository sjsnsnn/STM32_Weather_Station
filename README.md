## 🐛 技术难点与优化记录 (Debug & Optimization Log)

### 1. 传感器数值抖动导致状态频繁切换
- **遇到的挑战**：光敏传感器在阈值附近受环境光微小波动影响，数值跳动（例如在 980~1020 之间震荡），导致 OLED 屏幕上的状态在 DARK 和 BRIGHT 之间频繁闪烁，串口疯狂打印报警。
- **解决方案**：引入“迟滞状态机（Hysteresis）”。设置上下双阈值（下限 1000，上限 1200），并在代码中使用 `is_dark` 变量记录当前状态。只有当数值跨越上下限时才触发状态切换，有效避免了临界抖动。

### 2. printf 串口阻塞导致主循环响应延迟
- **遇到的挑战**：在 115200 波特率下，通过 `printf` 打印约 30 个字符需耗费约 2.6ms 的时间。在此期间 CPU 处于死等状态，阻塞了主循环中其他任务的执行。
- **解决方案**：暂时降低打印频率，采取“每隔 500 次循环打印一次”的策略。**下一步计划**：改用串口中断（IT）发送或 DMA 发送，释放 CPU 占用。

### 3. AD 转换死等导致的潜在死机风险（防御性编程）
- **遇到的挑战**：原始的 `while(ADC_GetFlagStatus(...))` 若是硬件故障导致标志位一直不置位，程序将死锁。
- **解决方案**：引入超时保护机制，加入 `timeout` 计数器。一旦超时，强制跳出循环返回错误码（0xFFFF），确保系统具备自我恢复能力。

### 4. 阻塞式延时导致系统响应迟缓
- **遇到的挑战**：原先在 `while(1)` 中使用的 `for(i=0; i<1000000; i++)` 属于阻塞式延时，导致CPU在延时期间无法响应其他任务，系统实时性极差。
- **解决方案**：配置 TIM2 产生 1ms 的硬件中断。在中断服务函数中维护 `volatile uint32_t g_sys_tick` 作为系统软时钟（Tick）。主循环采用“时间戳差值对比”的非阻塞方式，实现了任务每1秒执行一次，同时CPU能在空转期间随时响应其他中断（如串口/按键）。
